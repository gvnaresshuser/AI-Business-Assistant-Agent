AI Business Assistant — RAG Search
Business knowledge documents

Product manuals, warranty policies, return policies, vendor agreements and business procedures.


Document processing

Extract text → split into chunks → generate embeddings.


NeonDB + pgvector

Store document chunks, metadata and vector embeddings.


Semantic search and retrieval

Find the most relevant document chunks for a user's question.


Gemini generates the answer

Answers using retrieved document content, with relevant source references.


Example questions for students
- What is our warranty policy for Samsung televisions?
- Can a customer return a product after 15 days?
- What are the warranty conditions for laptops?
- What are the payment terms agreed with our vendors?
- Find the installation instructions for a particular product.
We will retain your existing SQL-based tools for sales, inventory, expenses and analytics. RAG will handle document-based knowledge rather than replacing those tools. This is the distinction we want students to understand.

Create the RAG document storage table
We will store document chunks and their embeddings in a separate table, keeping your existing business tables untouched.

Before creating it, we need to choose the embedding dimension. Let's use Google Gemini gemini-embedding-001 with 768 dimensions for this project.

Run this SQL in NeonDB:

CREATE TABLE IF NOT EXISTS agent_knowledge_chunks_biz_agent (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    business_id UUID NOT NULL
        REFERENCES biz_businesses_biz_agent(id),

    document_name VARCHAR(255) NOT NULL,

    chunk_index INTEGER NOT NULL,

    chunk_content TEXT NOT NULL,

    embedding VECTOR(768) NOT NULL,

    metadata JSONB DEFAULT '{}'::jsonb,

    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

Then create an index for business-level document retrieval:
CREATE INDEX IF NOT EXISTS
idx_knowledge_chunks_business_biz_agent
ON agent_knowledge_chunks_biz_agent(business_id);

And a vector similarity index:
CREATE INDEX IF NOT EXISTS
idx_knowledge_chunks_embedding_biz_agent
ON agent_knowledge_chunks_biz_agent
USING hnsw (embedding vector_cosine_ops);

Why 768 dimensions? Gemini's embedding model supports configurable output dimensions. We will explicitly request 768 dimensions when generating embeddings so they match the database column.

Understand the workflow
Suppose a user asks:

What is the warranty period for Samsung televisions?
1. Gemini converts the question into a 768-dimensional vector.
2. PostgreSQL compares it against stored document vectors.
3. The five most relevant chunks are returned.
4. The next stage will pass these chunks to Gemini to generate an answer grounded in the documents.


Connect RAG with Gemini
The next stage is to generate a natural-language answer using the retrieved document chunks.

For example:

User question: What is the warranty period for Samsung televisions?

RAG workflow:
1. Retrieve relevant warranty document chunks.
2. Pass those chunks and the question to Gemini.
3. Generate an answer based on the retrieved content.
4. Return the answer along with its source document references.
