Implement JWT invalidation
The approach:
1. Add a token_version column to auth_users_biz_agent.
2. Include the user's token version in the JWT during login.
3. Increment the version whenever the password changes.
4. Check the JWT version against the database on every authenticated request.
5. Reject older tokens with HTTP 401.
No Gemini API calls required.
First task – Update NeonDB
Open the NeonDB SQL Editor and execute:
ALTER TABLE auth_users_biz_agent
ADD COLUMN IF NOT EXISTS token_version INTEGER NOT NULL DEFAULT 0;

SELECT
    full_name,
    email,
    token_version
FROM auth_users_biz_agent
ORDER BY full_name;

Use the password-change API with a valid current password and a different new password.

Expected:
- HTTP 200
- Database token_version increments from 1 to 2 (assuming the previous password change already incremented it to 1).
